개발 워크스테이션 구축 과제 Workflow

1. 저장소 및 문서 구조 준비
   - GitHub 제출 저장소를 생성하고 로컬 저장소와 연결한다.
   - README.md, app/ 또는 src/, Dockerfile, evidence/ 디렉토리를 준비한다.
   - README에 프로젝트 개요, 환경, 체크리스트, 검증 결과, 트러블슈팅 섹션을 만든다.

2. 실행 환경 확인 및 기록
   - OS, 쉘, 터미널 종류를 확인한다.
   - docker --version, docker info, git --version을 실행한다.
   - 서울캠퍼스에서 Docker 데몬을 직접 사용할 수 없으면 OrbStack을 실행한 뒤 점검한다.
   - 명령어와 출력 결과를 README 코드 블록 또는 README에서 연결한 로그에 기록한다.

3. 터미널 기본 조작 실습
   - pwd와 ls -la로 현재 위치와 숨김 파일을 확인한다.
   - cd, mkdir, cp, mv, rm으로 이동, 생성, 복사, 이름 변경, 삭제를 수행한다.
   - cat 등의 명령으로 파일 내용을 확인하고 touch로 빈 파일을 생성한다.
   - 각 핵심 명령과 출력을 기록한다.

4. 파일 및 디렉토리 권한 실습
   - 파일 1개와 디렉토리 1개의 현재 권한을 ls -l 또는 ls -ld로 확인한다.
   - chmod로 파일과 디렉토리 권한을 변경한다(예: 644, 755).
   - 변경 전후 결과와 r/w/x 및 숫자 권한의 의미를 README에 설명한다.

5. Docker 기본 실행 및 운영 검증
   - hello-world 이미지를 받아 컨테이너 실행 성공을 확인한다.
   - ubuntu 컨테이너에 진입해 ls, echo 등의 명령을 수행한다.
   - attach와 exec, 컨테이너 종료와 백그라운드 유지의 차이를 관찰해 기록한다.
   - 이미지 다운로드 및 목록 확인, 컨테이너 실행·중지·목록 확인을 수행한다.
   - docker images, docker ps, docker ps -a, docker logs, docker stats 결과를 기록한다.

6. Dockerfile 기반 커스텀 웹 이미지 제작
   - NGINX/Apache 등의 웹 서버 베이스 또는 Linux 베이스 이미지를 선택한다.
   - 웹 소스와 Dockerfile을 직접 작성한다.
   - 선택한 베이스와 콘텐츠, 설정, 환경 변수, 헬스체크 등 각 커스텀 요소의 목적을 설명한다.
   - docker build로 이미지를 빌드하고 docker run으로 컨테이너를 실행한다.
   - 빌드 및 실행 명령과 핵심 출력을 기록한다.

7. 포트 매핑 검증
   - docker run -p <host_port>:<container_port> 형식으로 웹 컨테이너를 실행한다.
   - 브라우저 또는 curl로 localhost의 호스트 포트에 접속한다.
   - 브라우저 증거는 주소창의 포트와 응답 화면이 함께 보이도록 캡처한다.
   - 명령, 응답, 캡처 링크를 README에 추가한다.

8. 바인드 마운트 변경 반영 검증
Docker 볼륨을 생성하고 컨테이너에 연결한다.
컨테이너 삭제 전/후로 데이터를 확인하여 데이터가 유지됨을 증명한다.
기술 문서에 생성/연결/검증 절차(명령+출력)를 포함한다.
   - 호스트 소스 디렉토리를 컨테이너의 웹 콘텐츠 경로에 바인드 마운트한다.
   - 호스트 파일 변경 전후의 웹 응답을 비교한다.
   - 실행 명령과 변경 전후 결과를 기록한다.

이 작업을 수행하고 docker-volume.md를 작성해줘


9. Docker 볼륨 영속성 검증
   - docker volume create로 볼륨을 생성한다.
   - 첫 번째 컨테이너에 볼륨을 연결하고 파일을 저장해 내용을 확인한다.
   - 첫 번째 컨테이너를 삭제한다.
   - 새 컨테이너에 같은 볼륨을 연결해 기존 파일이 유지되는지 확인한다.
   - 생성, 연결, 삭제 전후 검증 명령과 출력을 기록한다.

10. Git 설정 및 GitHub/VSCode 연동
    - Git 사용자 이름, 이메일, 기본 브랜치를 설정한다.
    - git config --list 결과를 기록하되 개인정보는 필요한 만큼 마스킹한다.
    - VSCode에서 GitHub 로그인과 저장소 연동을 완료한다.
    - 원격 저장소와의 연동 증거를 민감정보 없이 캡처한다.

11. 기술 문서 완성
    - README에서 모든 수행 결과와 증거에 접근할 수 있게 링크를 정리한다.
    - 터미널, 권한, Docker, Dockerfile, 포트, 바인드 마운트, 볼륨, Git, GitHub 체크리스트를 갱신한다.
    - 문제 → 원인 가설 → 확인 → 해결 또는 대안 형식의 트러블슈팅을 2건 이상 작성한다.
    - 절대/상대 경로, 권한 표기, 이미지와 컨테이너, 포트 매핑, 볼륨, Git과 GitHub의 차이를 설명한다.

12. 보안 및 최종 재현성 점검
    - README, 로그, 이미지, Git 이력에서 토큰, 비밀번호, 개인키, 인증 코드 노출 여부를 확인한다.
    - 노출된 비밀이 있다면 문서와 이력에서 제거하고 해당 자격 증명을 재발급한다.
    - 개인 PC에 종속된 경로나 설정에는 대체 방법 또는 주의사항을 적는다.
    - 깨끗한 환경에서 README의 명령 순서만으로 빌드, 실행, 접속, 데이터 영속성을 다시 확인한다.
    - 최종 변경 사항을 커밋하고 GitHub에 푸시한 뒤 저장소 링크로 모든 산출물을 확인한다.

선택 보너스
   - 단일 서비스 Docker Compose 구성 및 up/down/ps/logs 검증
   - 웹 서버와 보조 서비스의 멀티 컨테이너 구성 및 네트워크 통신 확인
   - 환경 변수로 서버 설정 분리
   - GitHub SSH 키 기반 push 검증

증거 기록 원칙
   - 모든 로그에는 입력한 명령과 출력 결과를 함께 남긴다.
   - 브라우저 캡처에는 주소창(포트 포함)과 응답 화면을 함께 담는다.
   - 예시를 그대로 복사하지 않고 실제로 수행한 폴더명, 포트, 출력, 구성을 기록한다.
   - README만 읽어도 평가자가 전체 과정과 검증 방법을 재현할 수 있어야 한다.
